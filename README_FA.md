# BrainByte — Keyomars AI Agent v0.3.2

**نسخه اصلاح‌شده برای آزمایش واقعی AI Project Assistant و ضبط اولین ویدیوی بلند BrainByte.**

## دلیل این اصلاح

در نسخه 0.3.1، مدل محلی Qwen3:8b ممکن بود `validate_plan` را صدا نزند و به‌جای JSON صرفاً متن بنویسد. در نتیجه پنل «۰ از ۸ تسک» و «نیازمند اصلاح» نمایش می‌داد. زیادکردن Timeout این ایراد منطقی را رفع نمی‌کرد.

### معماری جدید: کنترل مراحل با Python

1. خود Python فایل‌های `README.md`، `notes.md`، `tasks.json`، `project_constraints.json` و `app_stub.py` را **فقط برای خواندن** بارگذاری می‌کند.
2. از Ollama/Qwen3 برنامه پنج‌روزه با **JSON Schema** می‌خواهد؛ مدل دیگر ملزم به انتخاب دستی ابزار `validate_plan` نیست. راهکار `format: { ...schema... }` در API رسمی Ollama پشتیبانی می‌شود.
3. **خود Python** برنامه را با `validate_plan` اعتبارسنجی می‌کند. اگر اشتباه باشد، خطای واقعی را به مدل برمی‌گرداند؛ حداکثر دو مرتبه اصلاح.
4. اگر مدل همچنان برنامه معتبر ندهد، یک **زمان‌بند قاعده‌محور مستقل Python** با رعایت پیش‌نیازها و ظرفیت، برنامه قابل اعتبارسنجی ارائه می‌کند. پنل صریحاً اعلام می‌کند که این برنامه **خروجی برنامه‌ریزی AI نیست**.
5. اگر حتی برنامه قاعده‌محور هم به علت محدودیت زمان یا داده‌های نامعتبر امکان‌پذیر نباشد، خطا اعلام می‌شود و **هیچ فایلی نوشته نمی‌شود**.
6. برنامه فقط پس از اعتبارسنجی و **تأیید صریح کاربر** (و تأیید جداگانه اضافه‌کاری، اگر لازم باشد) در `sample_project/output/plan.md` ذخیره می‌شود.

> توجه: برنامه‌ریزی جایگزین Python صرفاً مبتنی بر ساعت‌ها و وابستگی‌های ثبت‌شده در فایل نمونه است؛ کیفیت یا واقع‌بینی تخمین‌های انسانی را تضمین نمی‌کند.

## اجرای ویندوز

1. اگر نسخه‌های قبلی باز هستند، CMD آنها را با **Ctrl+C** ببند تا پورت 7860 آزاد شود.
2. فایل ZIP نسخه 0.3.2 را در **پوشه‌ای جدا** Extract کن. نسخه‌های قبلی را جایگزین نکن.
3. بررسی کن Ollama مدل را می‌شناسد:

   ```cmd
   ollama list
   ```

4. داخل پوشه `BrainByte_Keyomars_Agent_v0_3_2` فایل `Start_Keyomars.bat` را اجرا کن، یا:

   ```cmd
   python run_web.py
   ```

5. صفحه `http://127.0.0.1:7860` را باز کن و **شروع تحلیل پروژه** را بزن.
6. در لاگ‌ها باید «جمع‌آوری اطلاعات واقعی پروژه»، «کنترل ظرفیت، وابستگی و کارهای جاافتاده» و نتیجهٔ اعتبارسنجی را ببینی.
7. **در خروجی نمونه مورد انتظار:** ۵ روز، ۱۰ ساعت ظرفیت اصلی، ۱۰٫۵ ساعت کار ضروری، ۰٫۵ ساعت اضافه‌کاری نیازمند تأیید و توضیح موکول‌شدن `TF-07`.
8. اگر برنامه معتبر بود، در پنجره تأیید تیک **تأیید اضافه‌کاری** را بزن و روی دکمه تأیید ذخیره کلیک کن. این مرحله اختیاری و کاملاً تحت کنترل توست.
9. فایل ذخیره‌شده در `sample_project/output/plan.md` خواهد بود. پوشه `output` فقط **بعد از اولین ذخیره موفق** ساخته می‌شود.

### معنی وضعیت‌های پنل

- **AI + اعتبارسنج مستقل Python:** مدل JSON ساخته و اعتبارسنج مستقل تأیید کرده.
- **زمان‌بندی جایگزین قطعی Python:** مدل نتوانسته JSON معتبر بدهد؛ برنامه از قواعد `tasks.json` تولید شده، **نه توسط مدل**.
- **نیازمند تأیید اضافه‌کاری:** برنامه از نظر ساختاری معتبر است، ولی اضافه‌کاری بدون موافقت صریح ذخیره نمی‌شود.
- **خطا:** منابع یا ظرفیت اجازه تولید برنامه معتبر را نمی‌دهند، یا Ollama قابل دسترس نیست.

### نکات امنیتی

- پنل فقط به `127.0.0.1` متصل می‌شود؛ هیچ کلید API یا سرویس پولی لازم نیست.
- Agent فایل‌های پروژه یا وضعیت تسک‌ها را تغییر نمی‌دهد و ابزار shell / اجرای Python را در اختیار مدل قرار نمی‌دهد.
- `plan.md` فقط پس از تأیید و بررسی مجدد منبع `tasks.json` و محدودیت‌های پروژه نوشته می‌شود.
- نسخه نمونه برای فایل‌های **غیرمحرمانه** است. از داده‌های شرکت یا مشتری استفاده نکن.
- تأیید برنامه به معنی اجرای تسک‌های برنامه نیست؛ در ویدیو هم خروجی واقعی را به‌درستی توضیح بده.

## تست خودکار (بدون Ollama)

```cmd
python -m unittest discover -s tests -v
```

آزمون‌ها شامل: JSON صحیح، JSON غلط و اصلاح، استفاده از زمان‌بند جایگزین، ردکردن برنامه خارج از ظرفیت، تأیید اضافه‌کاری، جلوگیری از نوشتن قبل از تأیید، حفظ تسک‌های ورودی و مسدودشدن ذخیره در صورت تغییر فایل‌های منابع است.

**نکته:** این تست‌ها با مدل‌های شبیه‌سازی‌شده انجام می‌شوند. اجرای زنده `qwen3:8b` روی دستگاه تو باید یک بار تأیید شود.
